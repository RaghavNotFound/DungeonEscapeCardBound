# AGENTS Guide

## Project snapshot
- LibGDX multi-module game: `core` (game logic), `lwjgl3` (desktop launcher/packaging), `android` (mobile launcher).
- Entry flow is `Main -> HomeScreen -> ExplorationScreen` (`core/src/main/java/io/github/pkgde/Main.java`, `HomeScreen.java`, `ExplorationScreen.java`).
- Rendering is split: simulation in `GameWorld`, drawing/UI in `GameRenderer`, map loading in `MapManager`.

## Architecture and data flow
- `Main.create()` sets fullscreen-sized windowed mode, then opens `HomeScreen`.
- `HomeScreen` owns menu input + blur shader overlay (`SettingsOverlay`) and creates `ExplorationScreen` on PLAY.
- `ExplorationScreen` constructs `MapManager`, then wires `GameWorld(mapManager)` and `GameRenderer(world, camera, mapManager)`.
- `GameWorld.update()` advances `Player` and `Enemy`; `GameRenderer.render()` draws map -> entities -> debug collision outlines -> stamina bar.
- `Player` owns movement, stamina drain/regen, and arrow spawning; `Enemy` currently runs simple IDLE/CHASE AI with FOV/range checks.

## Map and asset contracts (critical)
- `MapManager.loadSpawns()` reads object layer `objects` and object names `playerSpawn` / `enemySpawn`.
- `MapManager.loadCollisions()` expects layers named exactly `wall`, `water`, `centerFire`.
- Keep naming/casing exact in Tiled maps; behavior is string-matched, not schema-driven.
- Current map is `assets/Maps/safeRoom.tmx`, but code loads `"maps/safeRoom.tmx"` in `ExplorationScreen`; this is a cross-platform casing risk (Windows vs Android/Linux).
- Asset list is auto-generated by Gradle task `generateAssetList` (root `build.gradle`) and written to `assets/assets.txt` during resource processing.

## Developer workflows
- Desktop run (primary loop): `./gradlew lwjgl3:run` (or `gradlew.bat lwjgl3:run` on Windows).
- Full build: `./gradlew build`; runnable fat jar: `./gradlew lwjgl3:jar`.
- Platform-specific jars: `./gradlew lwjgl3:jarWin`, `lwjgl3:jarLinux`, `lwjgl3:jarMac`.
- Android app start helper exists: `./gradlew android:run` (uses `adb` and `local.properties` / `ANDROID_SDK_ROOT`).
- If Gradle fails with `Unsupported class file major version 68` (see `build_error.txt`), run with a supported JDK for this wrapper/toolchain setup (project targets Java 17).

## Project-specific coding patterns
- Camera sizing follows map dimensions from TMX properties (`MapManager.getMapWidth/Height`) and a `FitViewport`.
- Player/enemy dimensions are hardcoded (`128x128`) and used directly for bounds and rendering alignment.
- Many textures are loaded directly in constructors (`Player`, `Enemy`) and manually disposed; keep dispose paths updated when adding assets.
- `Arrow` texture is static singleton (`Arrow.getTexture()`); call `Arrow.disposeTexture()` if you introduce lifecycle cleanup hooks.
- Existing menu/UI code is immediate-mode style (`ShapeRenderer` + `BitmapFont`) without Scene2D.

## Integration points and current gaps
- `PauseOverlay`, `InputHandler`, and `KeyBindings` are currently not wired into active screen flow.
- `MapManager` is only disposed if `GameWorld.dispose()` calls it (currently it does not), so map renderer/map lifetime should be reviewed when editing lifecycle.
- Desktop launcher (`lwjgl3/Lwjgl3Launcher.java`) applies maximized decorated windowed mode, not complete fullscreen.
- Android launcher is minimal (`AndroidLauncher` with immersive mode); any platform-specific input/file fixes should be isolated to launcher modules, not `core`.
